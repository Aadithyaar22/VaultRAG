E3 · Questions judges may ask, and honest answers

QuestionAnswer
How is this different from ordinary role-based access in a vector database?Filtering at search time is not enough: saved answers and in-flight answers can outlive a permission change. We attach every answer to the exact document and permission versions it used and re-check them at release time, and we never trust the vector store’s filter alone — the database decides.
Is it novel?We have not done a prior-art review, so we do not claim novelty. We claim a working, tested combination of known ideas with a specific “release-time re-validation” design.
What stops a poisoned document from hijacking the AI?Mainly the design: the AI has no tools, sees only documents the user may read, treats them as data, and cannot read other documents anyway. On top, we remove attack-like sentences. The detector itself is weak (about 20% on a public benchmark).
Does any data leave the server?Yes — the allowed passages go to Groq to write the answer. Forbidden passages never do. A server-side model is the planned fix; the code already supports switching the provider.
How do you use IBM Z?The app, tests and our ML models run on a LinuxONE z17 (s390x); we ran IBM’s AI/ML lab there. The Z AI accelerator and hardware encryption are planned, not used.
Quantum-safe?Not implemented. It is on the roadmap.
What if the AI makes things up?It must cite numbered evidence; answers without a valid citation are blocked; if the evidence does not answer, it must say so and we show “nothing I may share”. We cannot guarantee the wording is always right.
What happens if the permission check fails or is down?The answer is blocked, even saved ones. We prove this with a demo button and a test.
How did you test it?42 automated tests; a benchmark against two baselines; a live test with six real documents across six roles; an independent public injection benchmark. Reports are in the repo, including the failures we found.
Will it scale?Not as built: one node and SQLite. The permission logic does not depend on that; the storage would move to a replicated database and a separate authorization service.
Why does the administrator not see everything?Managing documents and reading them are different powers. Separating them reduces insider risk.

E4 · Team FAQ

QuestionAnswer
Who has the server key?Only the team lead. Share it privately if someone must log in; never in git or chat. Ask the lead to run server commands if unsure.
Can I open the live site?Yes: http://148.100.99.19:8000 (type the http:// and :8000). Use the demo cards; password demo-pass.
I changed the code. How do I get it on the server?Build the frontend, rsync, restart (C3). Run the tests first.
The demo looks broken or cluttered.Demo Controls → Reset demo data.
Where are the test reports?docs/REAL_DOCUMENT_TEST.md, docs/BENCHMARK.md, docs/IBM_LAB_EVIDENCE.md.
Can I add a document type or a role?Types: extract.py. Roles: the list in documents.py (ROLES) and the user interface lists; add tests for permissions.
Can I use a different AI provider?Set LLM_BASE_URL, LLM_MODEL, LLM_API_KEY to any OpenAI-compatible service.

E6 · Open-source software we use

FastAPI, Uvicorn, Pydantic, pydantic-settings, python-multipart, pypdf, pdfminer.six, python-docx, lxml, httpx, pytest, scikit-learn, fonttools, SQLite, React, Vite, Tailwind CSS, TypeScript. The AI model is openai/gpt-oss-120b, an open-weight model, served by Groq (a hosted service). Public data used only for testing: US government and university documents, the Apache License text, and the deepset/prompt-injections dataset (Apache-2.0).
